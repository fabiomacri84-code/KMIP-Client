# KMIP-Client — CipherTrust Manager integration

[Italiano](README.md) · **English**

KMIP-Client is a desktop application for testing KMIP integration with Thales CipherTrust Manager (CTM). It runs in its own window and uses PyKMIP. The application interface is in Italian; this documentation explains the workflow in English.

[Download Windows, Linux and macOS builds](https://github.com/fabiomacri84-code/KMIP-Client/releases/latest) · [User guide](docs/en/USER-GUIDE.md) · [Build and release guide](docs/en/BUILD-AND-RELEASE.md)

## What it tests

- Mutual TLS with a client certificate and trusted server CA.
- KMIP authentication and access to managed keys.
- AES-256 key creation, activation, lookup and retrieval.
- Encryption/decryption with a plaintext round-trip check.
- Key revocation and destruction.

The test client does not perform VM Encryption, vSAN encryption, VM storage policy configuration or the vCenter trust setup. Those operations must be tested in vSphere itself.

## Downloads

Each release includes three native packages and a SHA-256 checksum manifest:

| Platform | Package | Launch |
|---|---|---|
| Windows x64 | ZIP archive | `kmip-test-client.exe` |
| Linux x64 | TAR.GZ archive | `kmip-test-client` |
| macOS Apple Silicon / ARM64 | ZIP archive | `KMIP Test Client.app` |

Extract the complete archive. Keep the `_internal` directory alongside the executable on Windows and Linux. Python, Podman and an external openssl command are not required to run the desktop package. Windows and macOS packages are not signed with distribution certificates. The Linux package needs a modern glibc-based desktop and its normal graphics libraries; see the build guide.

New installations contain **no client certificates, private keys or laboratory settings**. Import your own files through the application. Existing user data is preserved when replacing the application package.

## CTM subdomains

For the manual subdomain workflow documented by this project:

1. Select the intended CTM subdomain and create or verify the local KMIP user in **Key Users**.
2. Open **KMIP → Client profile**, create a profile and expand **Certificate detail**.
3. Use this exact Common Name structure:

   ```text
   subdomain|subdomain||kmipuser
   ```

   There is one pipe between the domain names and **two pipes before the username**. For example: `vsphere|vsphere||kmipuser`.
4. Open **KMIP → Registered Clients → Add Client** in the same subdomain and register the client **manually** using that profile.
5. Download the client certificate and its private key directly from CTM. This workflow does **not** use a CSR generated by the application or automatic client registration.
6. Import the client certificate, its matching private key and the server CA chain into the application.
7. When KMIP username/password authentication is required, enter the exact full CN as the username, including both pipes before the username.

Thales uses the general syntax `<domain>|<auth-domain>||<username>`. The two domain names match when the local user belongs to the same domain used by the client. [Thales KMIP reference](https://docs-cybersec.thalesgroup.com/bundle/latest-cdsp-cm/page/reference/kmip-ref/index.html)

## vSphere TLS cipher suite

The vSphere integration procedure referenced by this project enables **`TLS_RSA_WITH_AES_256_CBC_SHA`** on the CTM KMIP interface:

1. Open **Admin Settings → Interfaces → KMIP → View/Edit**.
2. Move `TLS_RSA_WITH_AES_256_CBC_SHA` from **Disabled cipher suites** to the enabled list.
3. Save with **Update** and restart **nae-kmip** under **Admin Settings → Services**. Wait for the service to become healthy.

The PyKMIP client does **not** require or negotiate this RSA suite with its default TLS configuration. Keep compatible ECDHE/GCM suites enabled as well. A successful test with this app does not demonstrate that vSphere negotiates the required cipher suite. Check the integration requirements for the actual vSphere version and TLS profile in use. [Thales interface cipher-suite documentation](https://www.thalesdocs.com/ctp/cm/2.7/admin/cm_admin/interfaces/index.html)

## Key destruction

KMIP Destroy removes the cryptographic key material. CTM can retain the object's name, UID and metadata in the **Destroyed** state, so the object can remain visible in the CTM console. Full metadata deletion is a separate operation. [Thales KMIP reference](https://docs-cybersec.thalesgroup.com/bundle/latest-cdsp-cm/page/reference/kmip-ref/index.html)

## Versioning

The current version is defined in `app_version.py` and displayed in small text in the GUI and guide. Release archives include the version in their names. Versioned Git tags trigger native builds; a release is published only after all three packages pass their checks.
